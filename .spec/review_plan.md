# 全书自动化 Review 计划

## 目标
基于 `@.cursor/rules/constitution.md` 的核心规范，对全书 11 个 Markdown 文件（含前言）进行全面深度的“找茬”扫描。找出潜在的合规性漏洞、术语不一致、啰嗦表达以及格式错误，并生成结构化的 Review 报告。
**本次操作仅进行纯只读审查（Read-only Review），绝对不修改源文件。**

## 执行策略
启动 3 个并行的 AI 质控代理（Agent），按章节分组进行 Pass 1（内容密度）、Pass 2（技术一致性）和 Pass 3（跨章节逻辑）的全面交叉审查。审查结果将统一输出到 `.spec/reviews/` 目录下。

## 审查雷达重点
1. **违禁词拦截**：全域扫描是否有“密码加密”、“400 Bad Request”、“id: int”、“需求文档”、“设计文档”。
2. **格式排查**：AI 对话和外层嵌套代码块是否严格使用了四个反引号 ````，图表是否为纯 Mermaid 语法，表格是否左对齐。
3. **逻辑对齐**：第 6、7、8 章的 AC 编号引用是否严格对齐了第 5 章的 AC-1~AC-35（无编造、无错位）。比喻是否跨章重复。
4. **冗余探测**：探测啰嗦重复的段落、超过一句话的预防针/免责声明、口语化废话。

## 代理分工安排
- **Agent A**：负责 `00-前言.md` 及 `01`, `02` 章（输出：`.spec/reviews/report_00_02.md`）
- **Agent B**：负责 `03`, `04`, `05`, `06` 章（输出：`.spec/reviews/report_03_06.md`）
- **Agent C**：负责 `07`, `08`, `09`, `10` 章（输出：`.spec/reviews/report_07_10.md`）
