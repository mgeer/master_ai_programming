# 前言

## 这本书是写给谁的

写给**已经在用 AI 编程工具，但还没形成系统方法论**的程序员。

你可能已经试过让 ChatGPT、Claude 或 Copilot 帮你写代码，但体验不太好——输出的代码不符合预期、反复修改效率反而更低、AI 甚至会自信地编造不存在的 API（这叫"幻觉"）、不知道什么时候该用什么时候不该用。

这本书帮你解决这些问题。

## 这本书不是什么

- 不是 AI 原理科普（不讲大模型怎么训练的）
- 不是某个工具的操作手册（不讲 Cursor 的每个按钮怎么按）
- 不是提示词大全（不列 100 种提示词模板让你背）

## 这本书是什么

**一套 AI 辅助编程的方法论，来自一年实战经验的总结。**

过去一年，我在日常开发中大量使用 AI 编程工具，经历了从"新鲜好奇"到"反复踩坑"再到"形成体系"的过程。书中的每个方法、每条建议，都是在实际项目中验证过的——有些是我发现有效的做法，有些是我踩完坑后总结的教训。

核心内容三件事：

1. **怎么和 AI 说话**——CRC 三要素 + 多轮对话技巧
2. **怎么用 AI 做项目**——SDD 规范驱动开发（Constitution → Specify → Plan → Tasks → Implement）
3. **怎么保证质量**——规范先行 + 测试驱动 + 持续审查

方法论不绑定任何具体工具。无论你用 Cursor、Claude Code、Copilot 还是未来出现的新工具，这些方法都适用。

> **适用边界**：本书的方法论是为**可持续维护的生产项目**设计的。如果你只是想快速验证一个想法、做个演示 demo、或者测试 AI 的能力，一句话提示就够了，不需要这套方法论。但如果你的项目需要长期维护、团队协作、上线给真实用户使用——那么"能跑"远远不够，你需要的是可测试、可维护、可扩展的代码。这正是本书要解决的问题。

书中会提到两个和工具相关的概念，不同工具中叫法不同，但本质一样：

| 概念 | 说明 | Cursor | Claude Code | GitHub Copilot |
|------|------|--------|-------------|----------------|
| **规则文件** | 项目级规范，AI 自动读取并遵循 | `.cursor/rules/` | `CLAUDE.md` | `.github/copilot-instructions.md` |
| **文件引用** | 在对话中引用项目文件作为上下文 | `@文件名` | 自动读取项目文件 | `#文件名` |

本书以 Cursor 为示例演示，但你使用任何工具时，只需替换为对应的文件名和语法即可。

## 前置条件

**第一、二章**（CRC 三要素、多轮对话技巧）讲的是与 AI 沟通的通用方法，不需要编程基础也能理解核心思路。案例以通用场景为主、编程场景为辅，方法本身适用于任何 AI 对话——写作、分析、设计都一样。

**从第三章开始**（SDD 规范驱动开发），本书进入实战项目开发，需要以下基础：

- **编程能力**：至少熟悉一门编程语言，能独立完成基本的开发任务
- **AI 工具操作**：会使用 Cursor、Claude Code 等 AI 编程工具的 Agent 模式（不会的可以先在 B 站搜索"Cursor Agent 模式"或"Claude Code 入门"，花 20 分钟看个入门教程）
- **Markdown 语法**：本书的需求文档、架构文档、规则文件都用 Markdown 编写（5 分钟可学会，搜索"Markdown 基础语法"即可）

## 工具准备

练习本书内容，你需要一个 AI 编程工具。**任何一个都行**——Cursor、Windsurf、Claude Code、GitHub Copilot 等 AI IDE 或编程工具，也可以用 ChatGPT、Claude 等通用对话工具。

如果你还没有选定工具，建议从 [Cursor](https://cursor.com/) 开始。它是一款内置 AI 的代码编辑器，可以直接在编辑器中和 AI 对话、引用项目文件、自动应用代码修改。本书的实战案例在 Cursor 中操作最流畅，但所有方法论在任何工具中都适用。

## 怎么读这本书

**如果你时间充裕**：从第一章顺序读到最后。每章都有实战案例和练习题，边读边练效果最好。

**如果你想快速上手**：
- 先读第一章（CRC）和第二章（多轮对话）—— 30 分钟学会基本功，立刻能用
- 再读第三章（SDD 概述）—— 理解全貌
- 需要做项目时，按需阅读第四到八章

**全书的知识结构：**

```
第一章  CRC 三要素           ← 怎么把需求说清楚
第二章  多轮对话技巧          ← 怎么和 AI 持续协作
第三章  SDD 概述             ← 规范驱动开发的全景图
第四章  Constitution         ← 建立项目宪章，定规矩
第五章  Specify & Clarify    ← 编写功能规范，查漏补缺
第六章  Plan                 ← 领域建模与技术设计
第七章  Tasks & Implement    ← 拆任务、写测试、做实现
第八章  Feature 迭代实战      ← 用第二个需求走一遍完整循环
第九章  工具生态与最佳实践     ← 工具选型和避坑指南
附录    延伸学习资源           ← 进一步学习
```

## 关于案例

全书使用**"待办事项（Todo）应用"**作为贯穿案例，技术栈为 Python（FastAPI）后端 + Vue 前端。书中以后端 API 开发为主线展开演示，因此正文中常简称为"Todo API"。

选择这个案例的原因很简单：人人都能理解"待办事项"的业务逻辑，这样你可以把注意力集中在方法论本身，而不是业务细节上。

## 最后

AI 编程工具在快速迭代，今天的功能明天可能就变了。但有些东西不会变：**清晰的思考、结构化的表达、严谨的工程实践。**

这本书教的就是这些不会变的东西。工具是手段，方法论是内功。内功扎实了，什么工具都能用好。
