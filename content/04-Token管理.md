# 第四章：Token 管理

## 4.1 引言

**本章目标**：理解 token 的消耗机制，掌握保持对话高效的核心技巧。

用 AI 久了会发现两个问题：对话越来越贵、AI 越来越糊涂。根源是同一个——token 的消耗方式。

---

## 4.2 Token 是什么

Token 是大模型的计量单位，不等于"字"。一个汉字约等于 1.5-2 个 token，一行代码通常消耗 10-30 个 token，一张图片可能消耗数百个 token。

**每轮对话的消耗方式**：AI 每次回复都会把整段对话历史重新读一遍，对话越长携带的历史越重。Claude 有 prompt caching 机制，对重复出现的前缀（如每次都引用同一个文件）会大幅降低费率，但对话历史本身不断增长是事实。

**上下文窗口限制**：每个模型都有最大 token 上限（如 200k）。超限后 AI 开始"失忆"——忘记早期约定、前后矛盾、重复已做的工作。

| 操作 | Token 消耗 |
|------|-----------|
| 直接粘贴一个文件内容 | 高（文件全量 token） |
| 用 `@文件名` 引用文件 | 读取文件内容，但不固化进对话历史 |
| 带礼貌性寒暄的提示词 | 浪费 |
| 3C 结构化提示词 | 精准，无冗余 |

---

## 4.3 案例：小明的烧钱习惯

公司的 API 账单月底超预算，组长让大家排查 AI 工具的使用情况。小明一看自己的用量，傻眼了——他是用量最高的人之一。

**Before（粘贴文件的习惯）**

小明平时问 AI 的方式是这样的：

> 「他打开 `auth.py`，Ctrl+A，Ctrl+C，切到 Claude Code，Ctrl+V」
> 麻烦帮我看一下这段代码有没有安全问题，谢谢

`auth.py` 有 340 行，粘贴后消耗了约 **12,000 token**。这只是一个问题。他一天问了十几个这样的问题，加上对话历史的累积，每轮的成本越来越高。

更麻烦的是：到第 15 轮对话时，Claude 开始"忘事"——它忘记了第 3 轮说好"不要引入新依赖"，然后在第 15 轮建议他加一个新的 auth 库。小明不解：明明说好了啊？

这不是 Claude 变笨，是 token 超限后早期内容被挤出了上下文窗口。

**After（@ 引用 + 分段对话）**

了解 token 机制后，小明改了两个习惯：

**习惯一：用 `@` 代替粘贴**

```
@src/auth.py 审查安全漏洞，重点看权限校验逻辑
```

`@` 引用和粘贴都会让 Claude 看到文件内容，token 量接近。区别在于：粘贴的内容永久嵌入对话历史，此后每一轮都带着这 340 行；`@` 引用是按需读取，不会把文件内容固化进历史记录，对话历史保持干净。此外，同一文件被多次引用时，prompt caching 会降低重复读取的成本。

**习惯二：任务完成后开新对话**

完成一个功能 → 用 `@` 引用产出物开新对话，不在同一个对话里拖很长：

```
前一轮做完了用户登录模块，产出在 @app/routers/auth.py 和 @tests/test_auth.py。
现在开始做注册接口，需求是……
```

新对话从第 1 轮开始，成本回到最低点，AI 也不会"失忆"。

**习惯三：提前提炼项目知识（大项目必备）**

排查问题时，小明发现另一个坑：每个新对话，Claude 都需要重新读一遍项目里的十几个文件才能理解背景——路由层怎么组织、服务层有哪些、主要的数据模型是什么——这些每次都要重新花 token 去推断。

解决方案：用一次对话把项目知识提炼成一个文件，之后按需 `@` 引用：

> 分析这个项目的整体结构：主要模块、各模块职责、关键接口和数据流向。整理成 `docs/project-context.md`，控制在 200 行以内。

生成后的 `project-context.md` 大约 150-200 行，是整个项目知识的浓缩版。之后需要项目背景时：

```
@docs/project-context.md 帮我设计用户权限模块的接口
```

200 行的摘要替代了重新读 2,000 行源码——而且因为是稳定文件，prompt caching 的命中率很高。这个文件也可以放进 CLAUDE.md 的引用列表，让 Claude 每次对话自动加载（详见 Ch5）。

token 不是按"问题数量"收费的，是按"每轮携带的对话历史总量"收费的。粘贴文件等于每轮都在重复支付这 340 行的费用——从第 1 轮到第 20 轮，每一轮都付。

---

## 4.4 要点

**识别"高 token 陷阱"的检查清单：**
- 是否直接粘贴了文件内容？→ 改用 `@` 引用（避免固化进对话历史）
- 对话是否已超过 10 轮？→ 考虑分段
- 提示词是否有大量礼貌性语言？→ 删除，只保留 3C 核心

**对话分段判断依据**：当前阶段的目标是否已经完成？如果是，开启新对话，用 `@` 引用前序产出物继续。

**规则化**：把 token 节省习惯写入 CLAUDE.md，让 AI 自动遵守（详见 Ch5）。示例规则："如果用户直接粘贴了大段代码，提醒他们改用 @文件名 引用"。

---

## 4.5 本章小结

- Token 按对话历史累计消耗；Claude 有 prompt caching，重复引用同一内容成本更低
- `@` 引用和粘贴都会读取文件内容，区别是粘贴会固化进对话历史，`@` 不会
- 大项目：提前提炼项目知识到文件，之后 `@` 引用这份摘要，比每次重读源码省得多
- 上下文超限是 AI "变笨"最常见的原因，不是模型问题

**练习**：为你当前项目写 3 条 token 节省规则，格式参考上面的示例，保存备用（下一章会把它们写入 CLAUDE.md）。
