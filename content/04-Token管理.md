# 第四章：Token 管理

## 4.1 引言

**本章目标**：理解 token 的消耗机制，掌握保持对话高效的核心技巧。

用 AI 久了会发现两个问题：对话越来越贵、AI 越来越糊涂。根源是同一个——token 的消耗方式。

---

## 4.2 Token 是什么

Token 是大模型的计量单位，不等于"字"。一个汉字约等于 1.5-2 个 token，一行代码通常消耗 10-30 个 token，一张图片可能消耗数百个 token。

**每轮对话的消耗方式**：AI 每次回复都会把整段对话历史重新读一遍。10 轮对话，第 10 轮的成本 ≈ 前 9 轮的总和。

**上下文窗口限制**：每个模型都有最大 token 上限（如 200k）。超限后 AI 开始"失忆"——忘记早期约定、前后矛盾、重复已做的工作。

| 操作 | Token 消耗 |
|------|-----------|
| 直接粘贴一个文件内容 | 高（文件全量 token） |
| 用 `@文件名` 引用文件 | 低（仅引用路径） |
| 带礼貌性寒暄的提示词 | 浪费 |
| 3C 结构化提示词 | 精准，无冗余 |

---

## 4.3 案例

同一个任务，两种写法：

**写法 A（高 token 陷阱）**：把 200 行源代码粘贴到对话里，附上"麻烦帮我看一下这段代码有没有问题，谢谢"。

**写法 B**：`@src/auth.py` 请审查这个文件的安全漏洞，重点看权限校验逻辑。

写法 B 的 token 消耗约为写法 A 的 1/10，且指向更明确，AI 输出质量更高。

---

## 4.4 要点

**识别"高 token 陷阱"的检查清单：**
- 是否直接粘贴了文件内容？→ 改用 `@` 引用
- 对话是否已超过 10 轮？→ 考虑分段
- 提示词是否有大量礼貌性语言？→ 删除，只保留 3C 核心

**对话分段判断依据**：当前阶段的目标是否已经完成？如果是，开启新对话，用 `@` 引用前序产出物继续。

**规则化**：把 token 节省习惯写入 CLAUDE.md，让 AI 自动遵守（详见 Ch5）。示例规则："始终用 @ 引用文件，不要复制文件内容到对话中"。

---

## 4.5 本章小结

- Token 按对话历史累计消耗，长对话成本呈指数增长
- `@` 引用 vs 粘贴内容，效果相当，成本差距巨大
- 上下文超限是 AI "变笨"最常见的原因，不是模型问题

**练习**：为你当前项目写 3 条 token 节省规则，格式参考上面的示例，保存备用（下一章会把它们写入 CLAUDE.md）。
