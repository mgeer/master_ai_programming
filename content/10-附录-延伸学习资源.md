# 附录：延伸学习资源

本书介绍了 SDD（规范驱动开发）的核心方法论和实践流程。如果你想进一步深入，以下是值得关注的资源。

---

## SDD 规范与标准

- **Agent Skills — SDD 规范站点**
  [https://agentskills.io](https://agentskills.io)
  SDD 方法论的官方介绍站点，包含规范定义、流程说明和社区讨论。

- **SDD 学术论文**
  [arXiv:2602.00180](https://arxiv.org/abs/2602.00180)
  详细阐述规范驱动开发的理论基础、流程设计和实验验证。适合想深入了解方法论背后原理的读者。

## 工具与项目

- **GitHub Spec Kit**
  [https://github.com/github/spec-kit](https://github.com/github/spec-kit)
  GitHub 官方出品的 SDD 标准化工具链。提供支持自动创建目录、生成规范文档、以及兼容各种 AI 助手规则文件的命令行能力。

- **Anthropic Skills**
  [https://github.com/anthropics/skills](https://github.com/anthropics/skills)
  展示了如何为 AI 编程助手定义结构化约束，可作为编写 Constitution 和规则文件的参考。

## SDD 流程速查表

日常使用快速参考：

| 阶段 | 启动提示词要点 | 审查重点 | 产出物 |
|------|--------------|---------|--------|
| Constitution | "建立包含架构、技术栈、规范、安全、部署的项目宪章" | 规矩有无矛盾？是否过度设计？ | `.spec/constitution.md` |
| Specify | "编写包含用户故事、FR、NFR、AC 的功能规范" | 需求是否具体、可验证、无歧义？ | `.spec/features/xxx/spec.md` |
| Clarify | "审查规范，找出模糊、遗漏、矛盾并提问" | 模糊点是否厘清？AC 覆盖是否完整？ | 更新的 `spec.md` |
| Plan | "基于 spec 和 constitution，做技术方案设计" | 方案是否与 spec 和 constitution 匹配？ | `.spec/features/xxx/plan.md` |
| Tasks | "将 plan 拆解为可独立验证的任务列表" | 任务是否全覆盖需求且依赖清晰？ | `.spec/features/xxx/tasks.md` |
| Implement | "按任务要求，测试先行，实现功能" | 测试是否通过？代码是否合规并无隐患？ | `src/` 与 `tests/` 代码 |

> **提示**：每个阶段都必须引用上一个阶段的产出物和 `@constitution.md`。

## 推荐阅读顺序

进阶学习建议：

1. **先读 SDD 论文**（arXiv:2602.00180），掌握理论基础。
2. **试用 Spec Kit**，体验工具如何简化 SDD 流程。
3. **浏览 Anthropic Skills**，学习规则文件的高级约束写法。
4. **关注社区**，获取真实项目案例和避坑经验。

---

## 结语

SDD 是一把工具，帮你在 AI 编程时代保持对项目的完全掌控。当你想清楚了需求和设计，AI 便是最高效的执行者。

工具会不断更新换代，但"先想清楚再动手"的系统化思维将永远是你开发之路上的核心竞争力。

祝你驾驭 AI，编程愉快。
